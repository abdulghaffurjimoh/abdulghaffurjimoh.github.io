What the checks found

Most rows were usable.
The exceptions needed a decision.

18 repeated rows were merged into existing SKUs. 12 SKUs needed punctuation or case fixes. Nine price styles appeared across the files; eight were parsed to two decimal places and the POA rows were held back. The rest of the work was separating safe formatting changes from missing information.

37 SKUs were held back. 21 had an image problem, five had no firm price, four had an invalid barcode, four had no category and three had no brand. None of those values were guessed.

Issue counts are per SKU and describe this sample only. In this sample each blocked SKU has exactly one blocking issue, so the five review groups add up to 37. The full review queue has 53 entries: those 37 blocking cases plus 16 non-blocking duplicate-title checks.

Clear rules.
Traceable changes.

A useful handover should let someone retrace the work without guessing how the data changed.

Preserve the source.

The three raw files are kept unchanged. Every cleaned record carries its source file, source row and original SKU or price where the value changed.

Normalise only what is explicit.

SKU punctuation, currency markers, whitespace and case are standardised. 55 rows needed a whitespace or case fix. Product identity, pack size and descriptions are not rewritten.

Merge with a written rule.

Rows are grouped by normalised SKU. The richest row is kept; blanks are filled only from another row with the same SKU. Every removal is logged with both source rows.

Validate before export.

All 250 cleaned SKUs match the synthetic master and all 250 titles are unique. 246 barcodes pass GTIN validation; the four failures are blank and queued. Every ready price has two decimal places.

Stop at uncertainty.

Missing prices, images, brands, categories and invalid barcodes are not guessed. 37 SKUs are held with a next action. The cleaned row remains visible; the platform row is draft or hidden.

Export for the destination.

The Shopify file groups variants under one handle. The BigCommerce file stays one row per SKU. The generic file keeps all 250 records and every review flag.

Before a real store import

This is a synthetic sample, not client work. The image URLs, barcodes, prices and product names are fictional. “Ready” means the row passes the checks shown here, not that a live store will accept it. Test a small batch against the destination platform, confirm missing values with the supplier, and check the current platform schema before scaling up.

Built with Python and Excel-compatible CSV/XLSX files. The sample uses no real supplier or customer data. Full rules, source files, validation results and limitations are included in supplier-catalogue-evidence.zip.
